## Summary
- **Recommended Phase 5 route:** Run `perigee-host` as a privileged system service that follows `systemd-logind` (`seat0` `ActiveSession`), spawns/impersonates a per-session Wayland capture worker using `ext-image-copy-capture-v1` + `ext-image-capture-source-v1` (DMA-BUF + SHM) for both `cosmic-greeter` and user sessions, injects unattended pointer/keyboard input via `/dev/uinput` (with `libei`/portal as an optional unprivileged user-session mode), and uses a kernel `vkms` virtual connector (or dummy plug) for headless outputs until `cosmic-comp` supports virtual outputs.
- **Headless outputs (H1) do not exist in `cosmic-comp` today:** `cosmic-comp` only implements `x11`, `winit`, and `kms` backends (`cosmic-comp@0681eaf` `src/backend/mod.rs:25-46`), fails startup with `"Backend initialized without output"` if no DRM connector is connected (`src/backend/mod.rs:49-56`), and neither `wlr-output-management` nor `cosmic-output-management-unstable-v1` nor `xdg-desktop-portal-cosmic` (`src/screencast.rs:487-489`) can create virtual outputs.
- **Unattended capture (H2, H3, H9) works out of the box in `cosmic-comp` — including at the greeter and lock screen:** `ext-image-copy-capture-v1` and `ext-image-capture-source-v1` are advertised to every unsandboxed Wayland client (`client_not_sandboxed`, `cosmic-comp@0681eaf` `src/state.rs:168-174, 691-698`) with no consent dialog, supporting DMA-BUF, SHM, damage rectangles, and `ext-session-lock-v1` surfaces (`src/backend/render/mod.rs:844, 1429`).
- **Unattended pointer input (H4, H5) is blocked on Wayland/EIS in `cosmic-comp` — and `/dev/uinput` `EV_ABS` is single-output:** `cosmic-comp` exposes `zwp_virtual_keyboard_manager_v1` (`src/state.rs:718`) but **not** `zwlr_virtual_pointer_manager_v1`, and its `libei` D-Bus broker (`com.system76.CosmicComp.Ei`, `src/dbus/ei.rs:17-51`) lives on the **session** bus and hard-whitelists only `org.freedesktop.impl.portal.desktop.cosmic` and `com.system76.CosmicOSK`. Neither a session bus nor the portal runs inside `cosmic-greeter-start.sh`, leaving `/dev/uinput` as the only mechanism that works unattended at the greeter today — with the caveat that `cosmic-comp`'s non-EI `PointerMotionAbsolute` handler maps `libinput` `EV_ABS` strictly onto `seat.active_output()` (`src/input/mod.rs:791-801`), so crossing monitors via `/dev/uinput` requires relative `EV_REL` motion (`src/input/mod.rs:739-744`).
- **Greeter and lock-screen seat following (H6–H8) is tractable via `systemd-logind`:** `cosmic-greeter` runs under `greetd` as user `cosmic-greeter` (`exec cosmic-comp cosmic-greeter`, `cosmic-greeter@20af063` `cosmic-greeter-start.sh:3`, `cosmic-greeter.toml:7-9`), while user session locking uses `ext-session-lock-v1` inside the user's own `cosmic-comp` (`src/wayland/handlers/session_lock.rs:14-74`) without changing seats or sockets.

## Routes

### Route A: Portal-based (`xdg-desktop-portal` `RemoteDesktop` + `ScreenCast` + PipeWire + `libei`)
- **H1–H9 coverage:**
  - **H1 (Headless output):** Missing. `xdg-desktop-portal-cosmic` does not advertise `SOURCE_TYPE_VIRTUAL` (`xdg-desktop-portal-cosmic@7b0864c` `src/screencast.rs:486-489`), and `RemoteDesktop.Start` fails if `outputs().is_empty()` (`src/remote_desktop.rs:300-303`).
  - **H2, H9 (Capture + damage):** Covered in a logged-in user session via PipeWire (`SPA_DATA_DmaBuf` / `MemFd`), backed internally by `ext-image-copy-capture-v1`.
  - **H3, H5 (Unattended):** Partial in user sessions via `persist_mode = 2` (`PERSIST_UNTIL_REVOKED`) + `restore_data` (`src/remote_desktop.rs:308-344`) **after** a first interactive consent dialog. Fails completely if the monitor layout changes so saved outputs no longer resolve (`src/remote_desktop.rs:312`).
  - **H4 (Input):** Covered cleanly in user sessions via `ConnectToEIS` (`src/remote_desktop.rs:420-449`), giving `ei_keyboard`, `ei_text`, `ei_pointer`, and global multi-output `ei_pointer_absolute` (`cosmic-comp@0681eaf` `src/input/mod.rs:766-790`).
  - **H6, H7, H8 (Greeter + seat following):** **Does not work.** `cosmic-greeter-start.sh` launches only `cosmic-comp cosmic-greeter` with no session D-Bus, no `xdg-desktop-portal-cosmic`, and no PipeWire. Cannot render or log in from the greeter.
- **What Perigee would need to add:** `ashpd` (or `zbus` portal bindings), `pipewire` crate, `reis` (Rust `libei` client), a `systemd --user` service unit, and persistent storage for portal `restore_data` tokens. No root privilege required.
- **User-visible consent story:** Native COSMIC RemoteDesktop consent dialog on first connection per user (and again whenever monitor configuration changes). Zero consent available before login.
- **Risks:** Cannot satisfy the recorded v1 decision ("Unattended access including the login screen (`cosmic-greeter`), following the seat into the user session", `docs/audit/13-evaluation.md:121-131`). Useful only as an unprivileged fallback/screen-share mode.

### Route B: Direct compositor protocols (`ext-image-copy-capture-v1` + `cosmic-protocols` + `libei`)
- **H1–H9 coverage:**
  - **H1 (Headless output):** Missing in `cosmic-comp@0681eaf`; still requires kernel `vkms` or upstream `cosmic-comp` virtual-output support.
  - **H2, H3, H9 (Capture + unattended + damage):** Fully covered via `ext-image-copy-capture-v1` + `ext-image-capture-source-v1`, including DMA-BUF, SHM, damage rects, and `ext-session-lock-v1` lock screens, with no dialog.
  - **H4, H5 (Input + unattended):** **Broken without upstream `cosmic-comp` changes.** `cosmic-comp` has no `zwlr_virtual_pointer_manager_v1` (`src/state.rs:691-726`), and `com.system76.CosmicComp.Ei` (`src/dbus/ei.rs:17-51`) hard-rejects any caller other than `org.freedesktop.impl.portal.desktop.cosmic` or `com.system76.CosmicOSK` and only exists on the session D-Bus (absent at the greeter). Keyboard-only injection via `zwp_virtual_keyboard_manager_v1` works, but pointer injection is impossible.
  - **H6, H7, H8 (Greeter + seat following):** Still needs a privileged daemon watching `systemd-logind` to reach the active session's Wayland socket across UID boundaries.
- **What Perigee would need to add:** `wayland-client`, `wayland-protocols` (`ext-image-copy-capture-v1`, `ext-image-capture-source-v1`), `gbm`/`drm` for DMA-BUF allocation, `reis` (once `cosmic-comp` opens an authorized EIS path), plus upstream PRs to `cosmic-comp`.
- **User-visible consent story:** None (trust is established at Perigee's mTLS pairing boundary, `perigee-host pair`).
- **Risks:** **Hard-blocked on upstream `cosmic-comp` changes** for pointer injection (H4/H5) and virtual outputs (H1). Perigee cannot ship a working Linux host on current `cosmic-comp` using Route B alone.

### Route C: Privileged system service (`perigee-host`) + per-session Wayland capture worker + `/dev/uinput` (with optional `vkms` for headless)
- **H1–H9 coverage:**
  - **H1 (Headless output):** Pragmatic workaround today via Linux kernel `vkms` (virtual KMS connector with client-requested mode via `wlr-output-management` / custom mode or `vkms` configfs) or HDMI/DP EDID dummy plug, until `cosmic-comp` adds native virtual outputs. Note: `cosmic-comp`'s KMS `apply_config_for_outputs` (`cosmic-comp@0681eaf` `src/backend/kms/mod.rs:1111-1129`) selects only from the connector's advertised DRM modes (`"Unable to find matching mode"`), so dynamic resize to arbitrary client resolutions requires either `vkms` mode injection or an upstream `cosmic-comp` virtual-output feature.
  - **H2, H3, H9 (Capture + unattended + damage):** Fully covered on **both** `cosmic-greeter` and logged-in user sessions (including locked sessions) by spawning a per-session worker under the active session's UID/GID that connects to `$XDG_RUNTIME_DIR/wayland-*` and speaks `ext-image-copy-capture-v1` + `ext-image-capture-source-v1` (DMA-BUF preferred, SHM fallback).
  - **H4, H5 (Input + unattended):** Covered on **both** `cosmic-greeter` and logged-in user sessions via `/dev/uinput` (one virtual absolute tablet/pointer + one virtual relative pointer + one virtual keyboard) with zero consent dialogs and full support across greeter, lock screen, and user desktop. **Multi-monitor caveat (`Read`):** `cosmic-comp@0681eaf` `src/input/mod.rs:791-801` maps non-EI (`libinput` / `/dev/uinput`) `PointerMotionAbsolute` strictly onto `seat.active_output()`, so `/dev/uinput` `EV_ABS` alone cannot jump to another monitor; crossing monitors via `/dev/uinput` requires relative `EV_REL` pointer motion (`src/input/mod.rs:739-744`, which updates `seat.set_active_output(&output)`), or hybrid `libei` in user sessions.
  - **H6, H7, H8 (Greeter + seat following + privilege boundary):** `perigee-host` runs as a system service (`packaging/linux/perigee-host.service`), subscribes to `org.freedesktop.login1` `seat0` `ActiveSession` over the system D-Bus, and whenever the active session changes (boot → `cosmic-greeter` → `testuser` → logout → `cosmic-greeter`), tears down the old capture worker and spawns a new worker dropped to the target UID/GID. The QUIC endpoint, mTLS identity, and peer session stay alive across the login transition.
- **What Perigee would need to add:**
  - Crates: `zbus` (system bus `org.freedesktop.login1`), `wayland-client` + `wayland-protocols` (`staging` feature for `ext-image-copy-capture-v1` & `ext-image-capture-source-v1`, `wl_shm`, `zwp_linux_dmabuf_v1`), `drm` / `gbm` (for DMA-BUF allocation, already declared in workspace `Cargo.toml`), `evdev` or minimal `ioctl` wrapper for `/dev/uinput`.
  - Privileges & packaging: `perigee-host.service` runs as a dedicated system service (or `root` dropping capabilities to `CAP_SETUID`, `CAP_SETGID`, `CAP_NET_RAW` for VPN `SO_BINDTODEVICE`, and `/dev/uinput` write access; drop `CAP_SYS_ADMIN` unless needed for `vkms` setup, which is better handled by a one-time `modules-load.d` / udev rule). Separate the unprivileged Wayland capture worker binary (or `--capture-worker` subcommand) so Wayland/GBM/DRM parsing never runs as root.
- **User-visible consent story:** Unattended by design once paired via `perigee-host pair`. Pairing (`trusted_clients`) is the explicit host-owner consent boundary. Optional local visual indicator (e.g., notification or tray/panel status in a later phase) can inform a physical console user that a remote session is active.
- **Risks:**
  - **Multi-monitor `/dev/uinput` absolute pointer limitation (`Read`):** Because `cosmic-comp@0681eaf` `src/input/mod.rs:791-801` confines non-EI `PointerMotionAbsolute` to `seat.active_output()`, a single `/dev/uinput` `EV_ABS` device cannot switch monitors on its own. Phase 5 must either drive multi-monitor cursor traversal via relative `EV_REL` deltas (or a warp-to-edge + `EV_ABS` hybrid) or pair `/dev/uinput` at the greeter with `libei` in user sessions until upstream opens unattended EIS.
  - `/dev/uinput` bypasses Wayland input isolation (any keystroke goes to whatever has compositor focus, including password fields — which is required for greeter/lock-screen login, but raises the security bar on Perigee's mTLS + VPN binding).
  - `vkms` compatibility with `cosmic-comp`'s GBM/GLES KMS renderer (especially alongside a real GPU like AMD/NVIDIA/Intel) needs live kernel testing.
  - `cosmic-greeter` runtime dir / Wayland socket discovery race at startup needs a bounded retry/inotify wait.

## Recommendation

### Phase 5 first slice: Route C (with clean seams to adopt Route B's `libei` and native virtual outputs as upstream lands them)
1. **Why Route C:** It is the **only** route that satisfies the user's recorded v1 requirements (`docs/audit/13-evaluation.md:121-136`) — unattended access, `cosmic-greeter` login, seat following into the user session, DMA-BUF/SHM capture with damage tracking, and pointer+keyboard input — on **today's** `cosmic-comp@0681eaf` and `cosmic-greeter@20af063` without waiting on upstream compositor PRs.
2. **Keep the `FrameCapturer` and `InputInjector` traits decoupled** so that:
   - Capture uses standard `ext-image-copy-capture-v1` (which also works on Sway, Hyprland, wlroots, and future KWin/Mutter once supported, not just COSMIC).
   - Input starts with `/dev/uinput` for greeter + unattended user sessions, with a clean backend seam to plug in `libei` (`reis`) when `cosmic-comp` adds an authorized unattended EIS mechanism (or in unprivileged user-session portal mode).

### What to prototype first (ordered)
1. **Live Wayland capture spike (`ext-image-copy-capture-v1`, SHM first then DMA-BUF):** Standalone test/module connecting to the active `WAYLAND_DISPLAY`, enumerating `wl_output`s, creating an `ext_output_image_capture_source_manager_v1` source, capturing real frames with damage rects, and feeding them through `perigee-host`'s capture trait (replacing the `0x80` stub in `crates/perigee-host/src/backends/linux_capture.rs`).
2. **Live `/dev/uinput` input spike:** Create virtual keyboard + absolute (`EV_ABS`) + relative (`EV_REL`) pointer via `/dev/uinput`, verify keycodes, modifiers, single-output `EV_ABS` accuracy, and multi-monitor output switching via `EV_REL` in `cosmic-comp` (replacing the logging stub in `crates/perigee-host/src/backends/linux_input.rs`).
3. **Seat follower + greeter worker spike:** Subscribe to `org.freedesktop.login1` `seat0.ActiveSession`, verify `/run/user/<uid>/wayland-*` discovery for both `cosmic-greeter` and `testuser` (e.g. `192.0.2.10` client connecting at greeter, logging in as `testuser`, locking with `ext-session-lock-v1`, unlocking, and logging out back to greeter without dropping the QUIC session).
4. **Headless `vkms` spike:** Test `modprobe vkms` (with no physical monitor attached) under `cosmic-comp`'s `kms` backend to verify whether `cosmic-comp` initializes, renders, and serves `ext-image-copy-capture-v1` frames on a `vkms` connector, and whether `vkms` configfs dynamic modes allow client-driven resize (`ResizeRequest`).
5. **Real video codec + client presentation:** Wire a real encoder/decoder (decision pending in Phase 5 planning) and bare `winit`/`wgpu` client window to close the vertical slice.
